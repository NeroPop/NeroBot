# NeroBot

**NeroBot** is a Discord bot with a cat gallery, quotes, conversation prompts, a meme maker, reminders and a few
jokes. It is named after Nero the cat, and it runs on slash commands (you type `/` and pick a command).

This file explains everything, starting from zero. You do not need to know how Discord bots work.

| Quick facts | |
|---|---|
| Language | JavaScript (Node.js 24 or newer) |
| Discord library | [discord.js](https://discord.js.org) version 14 |
| Where data lives | Google Sheets (no database to run) |
| Code lives at | https://github.com/NeroPop/NeroBot (branch `main`) |
| Runs on | [Wispbyte](https://wispbyte.com), which pulls `main` from GitHub on every start |

## 1. What the bot does

**Slash commands** (typed starting with `/`):

| Command | What it does |
|---|---|
| `/features` | Lists every command and what it does, in pages with Back and Next buttons. |
| `/ping` | Replies "pong" so you can tell the bot is alive. |
| `/hello` | Says hello with a random greeting. |
| `/nero`, `/leone` | Names Nero and Leone. |
| `/day` | Shows the current day, date and time. |
| `/rate` | Rates anything out of 10. Tea, Nero, Leone, Leontine and Jack get 11/10. |
| `/say` | Makes the bot say something. |
| `/treat` | Gives NeroBot a treat. He replies and reacts happily. |
| `/home` | Shows a random picture of North Wales. |
| `/portfolio` | Shows Jack Myrick's portfolio with a button to the website. |
| `/cat`, `/catname`, `/catlist`, `/addcat` | The cat gallery. |
| `/quote`, `/quoteperson`, `/quotelist`, `/addquote` | The quote library. |
| `/prompt`, `/addprompt` | Conversation prompts. |
| `/meme`, `/addmemetext` | The meme maker. |
| `/suggestion` | Sends an idea for a new bot feature. |
| `/reminder`, `/reminderdm`, `/reminderlist` | Reminders in a channel, in a DM, and the list of waiting ones. |
| `/botchannel` | Chooses the channel where this server gets announcements. Needs Manage Server. |
| `/checkdebt` | Shows how much a person owes Nero. |
| `/addinvoice` | **Owner only.** Records that someone owes Nero money. |
| `/previewchangelog` | **Owner only.** Shows a private preview of the announcement. |
| `/featureupdatechangelog` | **Owner only.** Sends the announcement to every server. |

The three owner-only commands are hidden from `/features`. Anyone else who tries them gets a private
"Only Nero's owner can use this command."

**Chat triggers** (the bot reacts to words in normal messages, with no command needed):

| Someone says | The bot does |
|---|---|
| the word "tea" | Replies with a random tea quote. |
| 👀 | Reacts with 👀. |

**On its own, without anyone asking:**

- **Reminders**: when a reminder's time arrives, the bot posts it in the channel (pinging the person) or sends it
  as a direct message.

## 2. How the project is organised

```
NeroBot/
|
|-- index.js            The starting point. Running this file starts the bot.
|-- config.js           Every setting that is not secret (owner ID, sheet IDs, reminder limits...). Safe to share.
|-- README.md           This file.
|-- package.json        Lists the packages the bot needs, and the "npm run check" shortcut.
|-- package-lock.json   The exact versions of those packages. Generated by npm, do not edit.
|-- .gitignore          Tells git which files must never be uploaded (secrets, node_modules).
|-- .env                YOUR SECRETS. Created by hand on each machine. Never uploaded. (see section 6)
|
|-- commands/           One file per slash command. The file name IS the command name.
|-- triggers/           One file per chat trigger (the bot reacting to words in messages).
|-- images/             Pictures the bot posts (Nero_Knight.png, used by /portfolio).
|
|-- services/           Jobs that keep running in the background.
|     |-- reminders.js       Keeps the reminders, watches the clock, and sends them.
|
|-- lib/                Shared helper code that the files above use.
|     |-- loadFiles.js       Reads the commands, triggers and services folders and checks the files.
|     |-- sheets.js          Everything to do with Google Sheets (signing in, reading, writing).
|     |-- parseWhen.js       Understands "tomorrow 9am", "2pm in 3 months", "25 dec 2pm" and so on.
|     |-- timeUtils.js       Dates and times in a time zone (summer time, month lengths...).
|     |-- reminderCommand.js The shared part of /reminder and /reminderdm.
|     |-- paginate.js        Pages with Back and Next buttons (used by /features and /quotelist).
|     |-- changelog.js       The text of the latest announcement.
|     |-- taskQueue.js       Makes sure only one job changes a spreadsheet at a time.
|     |-- random.js          Small helpers for picking random numbers and items.
|     |-- text.js            Small helpers for text (shortening, checking web addresses).
|
|-- scripts/            Tools you run by hand.
      |-- check.js           The safety check. Run it with "npm run check" (see section 7).
```

**The one-sentence version of each folder:**

- `commands/` and `triggers/` are the **features you add to**. Each one is a small, separate file.
- `services/` is the **machinery** for the feature that needs a clock (reminders).
- `lib/` is **shared tools**, so the same code is not written twice.
- `scripts/` is **tools for you**, not for the bot.

## 3. How it works, in plain words

**Starting up.** When `index.js` runs it does these things in order:

1. Reads the secrets from the `.env` file.
2. Loads every file in `commands/`, `triggers/` and `services/`. (If any file is written wrongly, it says which
   one and stops.)
3. Logs in to Discord.
4. Tells Discord the list of slash commands. This happens on **every start**, so adding or deleting a file in
   `commands/` and restarting is all it takes.
5. Checks it can open every Google Sheet, and prints a line for each one.
6. Starts the background services (the reminder sender).

**While running:**

- When someone uses a **slash command**, the matching file in `commands/` handles it. If it breaks, the person
  gets a short private "something went wrong" message and the details (with the file name) are written to the
  console. One broken command can never stop the others.
- When someone sends a **message**, the bot (ignoring other bots) tests it against every trigger's `pattern`.
  Each trigger that matches runs. A broken trigger can never stop the others.
- **Reminders** run on a timer. The bot keeps a copy of the reminders sheet in memory, checks the clock against it
  every 15 seconds, and re-reads the sheet every 5 minutes (Google limits how often a bot may ask for data).

**Google Sheets is the bot's memory.** Everything that must survive a restart (cats, quotes, prompts, reminders,
announcement channels, debts) is saved in a spreadsheet. That means you can restart or move the bot to another
computer and nothing is lost, and you can look at (and carefully edit) the data yourself.

**Time zones.** Clock times people type for reminders are read in UK time by default (`timezone` in `config.js`),
and the bot handles the clocks going forward and back. Reminders can also take a `timezone` option. Times shown
in Discord messages use Discord's own timestamps, so each person sees them in **their own** time zone.

## 4. The features in detail

### The fun commands

`/hello`, `/nero`, `/leone`, `/ping`, `/day`, `/home`, `/portfolio` and `/treat` do what their descriptions say.
The lists they choose from (greetings, North Wales pictures, treat replies) are at the top of each command file, so
adding one is adding a line.

- `/rate item:<anything>` gives a random rating from 0/10 to 10/10. If the text contains the **whole word** tea,
  nero, leone, leontine or jack, it gives 11/10 (so "steak" does not count).
- `/say message:<text>` posts the words as a normal message from the bot, and tells you "Sent!" privately. The bot
  can ping people, but never `@everyone` or roles.
- `/treat` posts a card and then reacts to its own reply with 🍪, 🐾, 😻 or 💙. The reaction needs the **Add
  Reactions** permission.
- `/day` uses the time zone in `config.js`.

### `/features`

Shows every command except the hidden ones, 15 to a page, with Back and Next buttons. The list **builds itself**
from the files in `commands/`, using each command's description, so a new command appears by itself. To keep a
command off the list, add `hidden: true,` to its file (see "Everyday tasks").

### Cats

The cats are in the **Cats** sheet: column A is the name and column B is a picture link. A cat can have many rows.

| Command | What it does |
|---|---|
| `/cat` | A random cat picture with its name and a fun caption. |
| `/catname name:Nero` | A random picture of one cat. Capital letters do not matter. |
| `/catlist` | Every cat name once, A to Z. |
| `/addcat name:Nero link:https://...` | Adds a cat. The link must start with `http://` or `https://`. |

### Quotes

The quotes are in the **Quotes** sheet: column A is the author and column B is the quote.

| Command | What it does |
|---|---|
| `/quote` | A random quote. |
| `/quoteperson author:Terry Pratchett` | A random quote by one author. |
| `/quotelist author:Terry Pratchett` | Every quote by one author, 10 to a page, with Previous and Next buttons. |
| `/addquote author:... quote:...` | Adds a quote. The author can be more than one word. |

### Prompts, memes and suggestions

| Command | What it does |
|---|---|
| `/prompt` | A random conversation prompt, crediting who suggested it. |
| `/addprompt prompt:...` | Adds a prompt, crediting your server nickname. |
| `/meme` | Picks two pieces of text from the **Meme text** sheet and a random picture from [Imgflip](https://imgflip.com), and puts the text on it. |
| `/addmemetext text:...` | Adds text to the Meme text sheet. |
| `/suggestion idea:...` | Saves an idea for a new feature in the **Suggestions** sheet. |

`/meme` needs an Imgflip account. Its login is two secrets in the `.env` file (see section 6). Without them the
command says "The meme maker is not set up yet" and writes why in the console.

### Reminders

| Command | What it does |
|---|---|
| `/reminder when:... message:...` | At the chosen time the bot posts in the channel where you set it, pinging you. |
| `/reminderdm when:... message:...` | The same, but sent to you in a direct message. |
| `/reminderlist` | Shows your waiting reminders and the time left. Only you see the answer. |

Both set commands have an optional `timezone` box (for example `America/New_York`). Without it, clock times are read
as UK time.

**What you can put in the `when` box** (capital letters, commas and little words like "on", "at", "in" and "next" do
not matter):

| You type | Meaning |
|---|---|
| `30m`, `2h 30m`, `5 minutes`, `1 day 2 hours` | That long from now. Units: seconds (s), minutes (m), hours (h), days (d), weeks (w), months (mo), years (y). |
| `in 2 weeks`, `3 months` | That long from now, keeping the same time of day. |
| `tomorrow 9am`, `today 6pm`, `tonight 9pm` | That time tomorrow or today. `today` with a time that has gone is refused. |
| `friday 6pm`, `sat 19:20`, `7:20pm on saturday` | That time on the **next** such day. If it is that day and the time has gone, it means next week. |
| `25 dec 2pm`, `dec 25th 2pm`, `25/12 2pm`, `25/12/2027 14:30`, `2027-12-25 9am` | That date and time. With no year it means the next time that date comes round. |
| `2pm in 3 months`, `in 3 months at 2pm`, `9am in 2 weeks` | The date after the wait, at that time. |
| `7:20pm`, `19:20`, `9am`, `noon`, `midnight` | The next time the clock reads that. With no am or pm it is the 24 hour clock. |

After you set a reminder the bot shows you the full day and date it understood, so you can check it. One month
after 31 January is 28 February (the last day of that month). The days, weeks, months and years keep the clock time
the same, even when the clocks change.

**The rules:**

- A reminder must be at least a moment in the future, and at most 730 days ahead (`reminders.maxAheadDays`).
- If the bot was offline when a reminder was due, it still sends it when it comes back.
- If sending fails, the bot tries again after 2 minutes, and gives up after 3 tries in total.
- Reminders are saved in the **Reminders** sheet, so a restart loses nothing.
- Only the person being reminded can be pinged by a reminder, whatever the message says.

### Announcements

NeroBot can send one announcement (the "changelog") to every server it is in.

| Command | What it does |
|---|---|
| `/botchannel` | Run it in the channel where the server should get announcements. It is saved in the **Announcement channels** sheet. Run it again elsewhere to change it. Needs the Manage Server permission. |
| `/previewchangelog` | **Owner only.** Shows the announcement to you only, so you can read it first. |
| `/featureupdatechangelog` | **Owner only.** Sends it to every server: to its `/botchannel` channel, otherwise the system channel, otherwise the first channel the bot can write in. |

The text of the announcement is in `lib/changelog.js`. It refuses to send while `date` is empty (that means it is
still a draft). See "Everyday tasks" for how to write and send one.

### Debts

`/addinvoice name:Sam amount:12.50 reason:Cat treats` (owner only) records an invoice, and `/checkdebt name:Sam`
tells anyone how much a person owes. Capital letters do not matter in names. See the **Debts** sheet in section 5.

### Chat triggers

Each trigger is one file in `triggers/`. They work in **every channel the bot can read**, in every server it is in.
Capital letters never matter.

| File | Notes |
|---|---|
| `tea.js` | The whole word "tea". "team", "steak" and "instead" do not count. Replies with a random tea quote. |
| `eyes.js` | The 👀 emoji. Reacts with 👀. Needs the **Add Reactions** permission. |

A message with both "tea" and 👀 gets both replies.

## 5. The Google Sheets

The bot uses **eight spreadsheets**. Their IDs are in `config.js` under `sheetIds`. Each must be **shared with the
bot's service account email as Editor** (see section 7). The "ID" of a spreadsheet is the long part of its web
address between `/d/` and `/edit`.

The bot reads columns **by position** (column A, column B...), not by heading, so the headings in row 1 are for
humans and can say anything. Row 1 is skipped when reading.

| Sheet (`sheetIds` name) | Tab | Columns |
|---|---|---|
| **Cats** (`cats`) | `Sheet1` | A: cat name, B: picture link |
| **Quotes** (`quotes`) | `Sheet1` | A: author, B: quote |
| **Prompts** (`prompts`) | `Sheet1` | A: who suggested it, B: the prompt |
| **Meme text** (`memeText`) | `Sheet1` | A: the words that can go on a meme, B: who added them. `/meme` only reads column A. |
| **Suggestions** (`suggestions`) | `Sheet1` | A: Discord username, B: the idea |
| **Debts** (`debts`) | `Totals` | A: person's name, B: total they owe (this is what `/checkdebt` shows) |
| | `Invoice` | A: name, B: date, C: reason, D: amount |
| **Reminders** (`reminders`) | `Reminders` | A: user ID, B: time to send (milliseconds), C: message, D: channel ID (empty means DM), E: sent (`TRUE` or `FALSE`) |
| **Announcement channels** (`announcementChannels`) | `Sheet1` | A: server ID, B: channel ID |

**What is safe to edit by hand:**

- **Cats, Quotes, Prompts, Suggestions:** they are yours. Add, remove and sort rows.
- **Reminders:** setting `Sent` to `TRUE` cancels a waiting reminder. The bot notices edits within 5 minutes.
- **Debts:** if `Totals` column B is a formula that adds up the `Invoice` tab, leave the formulas alone. The bot only writes a new person's name in column A.
- **Announcement channels:** delete a row to stop a server getting announcements.

## 6. Settings and secrets

There are two places for settings, and the difference matters:

| | `config.js` | `.env` |
|---|---|---|
| Holds | Normal settings: owner ID, sheet IDs, time zone, reminder limits | **Secrets**: the Discord token, the Google key, the Imgflip login |
| Uploaded to GitHub? | **Yes**, it is meant to be | **Never.** `.gitignore` blocks it. |
| Edit when | You want to change how the bot behaves | You set up a new machine, or a secret changes |

### `config.js`

Every setting has a comment next to it explaining it. The sections:

| Setting | What it controls |
|---|---|
| `ownerId` | The Discord user ID of the owner, for the owner-only commands. |
| `timezone` | The time zone for `/day`, the invoice date, and reminder clock times. |
| `sheetIds` | The eight Google spreadsheets (see section 5). |
| `reminders` | How far ahead a reminder can be, how often the clock and sheet are checked, and the retry rules. |
| `sheetTabs` | The tab name used in each spreadsheet. |

If a value is written wrongly, `npm run check` names the exact setting and explains what to fix.

### `.env` (the secrets file)

Create a plain text file called `.env` (nothing before the dot) in the main project folder, with these lines:

```
DISCORD_TOKEN=your bot token
GOOGLE_SERVICE_ACCOUNT_EMAIL=the client_email value from the Google key file
GOOGLE_PRIVATE_KEY=the private_key value from the Google key file
IMGFLIP_USERNAME=your Imgflip username
IMGFLIP_PASSWORD=your Imgflip password
```

| Variable | What it is | Where to get it |
|---|---|---|
| `DISCORD_TOKEN` | The bot's password for Discord | Developer Portal, **Bot** page, **Reset Token** (shown once) |
| `GOOGLE_SERVICE_ACCOUNT_EMAIL` | The bot's Google "robot account" address | The `client_email` line in the downloaded Google JSON key file |
| `GOOGLE_PRIVATE_KEY` | The robot account's secret key | The `private_key` line in the same file |
| `IMGFLIP_USERNAME`, `IMGFLIP_PASSWORD` | The Imgflip account used by `/meme` | Your account at imgflip.com |

Older versions of this bot used the names `TOKEN` and `GOOGLE_CLIENT_EMAIL`. They are not read any more. Any other
lines in the file (like an old `SESSION_SECRET`) are ignored.

Pasting is forgiving: the bot removes stray quote marks, spaces and commas, accepts the key with real line breaks or
with `\n` written out, and checks it can be read. If something is still wrong, the console says what.

**Treat these values like passwords.** Never paste them in chat, screenshots or GitHub. If one leaks, reset the
token in the Developer Portal, delete the Google key and make a new one, or change the Imgflip password.

## 7. Setting it up from scratch

You need: a computer with [Node.js](https://nodejs.org) **24 or newer** and [git](https://git-scm.com), a Discord
account, a Google account, and a GitHub account.

### Step 1. Get the code

```bash
git clone https://github.com/NeroPop/NeroBot.git
```

Then, in a terminal inside the new folder, install the packages the bot needs:

```bash
npm install
```

### Step 2. Make the Discord application

1. Go to the [Discord Developer Portal](https://discord.com/developers/applications) and click **New Application**.
2. **Bot** page: click **Reset Token** and copy it somewhere safe. This is your `DISCORD_TOKEN` (it is shown only once).
3. Same page, **Privileged Gateway Intents**: switch **Message Content Intent ON** (the chat triggers cannot work
   without it). Leave **Presence** and **Server Members** off, because the bot does not use them.
4. **General Information** page: copy the **Application ID**.
5. Build the invite link by putting the Application ID into this address (it asks for the `bot` and
   `applications.commands` scopes, **both are needed**, and the permissions the bot uses):

   ```
   https://discord.com/oauth2/authorize?client_id=YOUR_APPLICATION_ID&scope=bot%20applications.commands&permissions=274878286912
   ```

   The permissions in that number are View Channels, Send Messages, Send Messages in Threads, Embed Links,
   Attach Files, Add Reactions, Read Message History and Use External Emojis.
6. Open the link and add the bot to your server.

**Slash commands need the `applications.commands` scope in each server.** A server that added the bot a long time
ago may not have it, so the commands would not appear there. Opening the link above again, and choosing that server,
fixes it. The bot stays in the server and nothing is lost.

### Step 3. Make the Google "robot account"

1. Go to the [Google Cloud console](https://console.cloud.google.com) and create a new project.
2. **APIs & Services**, **Library**: find **Google Sheets API** and click **Enable**.
3. **IAM & Admin**, **Service Accounts**: create a service account (any name). No roles are needed.
4. Open it, go to **Keys**, **Add key**, **Create new key**, **JSON**. A file downloads, **once**. Keep it safe
   and never upload it to GitHub (`.gitignore` already blocks the usual file names).
5. Open that JSON file in a text editor. You need two values from it: `client_email` and `private_key`.

### Step 4. Make and share the spreadsheets

1. Create the eight spreadsheets listed in section 5 (or use your existing ones), each with the right tab name.
2. For each one: click **Share**, paste the `client_email` address, set it to **Editor**, untick "Notify people".
3. Copy each spreadsheet's ID into `config.js` under `sheetIds`.
4. Put your own Discord user ID in `ownerId` in `config.js`.

### Step 5. Add your secrets

Create the `.env` file described in section 6 with your five values.

### Step 6. Run the safety check

```bash
npm run check
```

This checks, **without** needing the token or the internet, that every command, trigger and service file is written
correctly, that each trigger's example messages behave as they should, that the settings in `config.js` make sense,
that the changelog fits inside Discord's limits, that the secrets are ignored by git, and that no file contains an
em-dash. It ends with `All checks passed. Safe to push.` or tells you exactly what to fix. **Run it before every
push.**

### Step 7. Start the bot

```bash
npm start
```

A healthy start prints something like this (the numbers will differ):

```
Logged in as NeroBot#1234
Registered 32 slash command(s).
Connected to Google Sheet "Cats" (cats).
Connected to Google Sheet "Quotes" (quotes).
... one line for each of the eight sheets ...
Service "reminders" is running (0 waiting).
```

**Only ever run ONE copy of the bot with the same token.** Two copies would both answer every message and both
change the same spreadsheets. If you test on your own computer, stop the hosted one first.

New slash commands can take a few minutes to appear in Discord. Press `Ctrl+R` to refresh Discord if they do not.

## 8. Hosting and deploying on Wispbyte

The bot only works while it is running, so it lives on a host that is always on. NeroBot is on
[Wispbyte](https://wispbyte.com), which uses the same kind of control panel as Pterodactyl.

**How deploying works:** you push your changes to the `main` branch on GitHub. When the server **starts**, it pulls
the latest code from GitHub and runs `npm install`. So the routine is:

1. Run `npm run check`.
2. Commit and push to `main`.
3. **Restart the server** in the panel. The new code is now live.

### Server settings (the Startup page)

| Setting | Value |
|---|---|
| Docker image | **Node.js 24** (`nodejs_24`). Node 22 or older will not work. |
| Git repo address | `https://github.com/NeroPop/NeroBot.git` |
| Install branch | `main` |
| User uploaded files | **Off** |
| Auto update | **1** (pulls the latest code at every start. `0` means it never does.) |
| Main file | `index.js` |
| Additional node packages | **empty** (`package.json` already lists everything, and `npm install` installs it) |
| Uninstall node packages | **empty** |
| Startup command | The panel's standard Node.js command. It should end by running `node "/home/container/${MAIN_FILE}"` once, with no second `node index.js` line after it. |

The standard command looks like this (the `${...}` parts are filled in by the panel from the settings above):

```text
if [[ -d .git ]] && [[ ${AUTO_UPDATE} == "1" ]]; then git pull; fi; if [[ ! -z ${NODE_PACKAGES} ]]; then /usr/local/bin/npm install ${NODE_PACKAGES}; fi; if [[ ! -z ${UNNODE_PACKAGES} ]]; then /usr/local/bin/npm uninstall ${UNNODE_PACKAGES}; fi; if [ -f /home/container/package.json ]; then /usr/local/bin/npm install; fi; /usr/local/bin/node "/home/container/${MAIN_FILE}" ${NODE_ARGS}
```

What each part does, in order: pull the latest code (only when Auto update is 1), install any "additional" packages,
uninstall any "uninstall" packages, run `npm install` to install everything in `package.json`, then start the bot.

Then create the `.env` file (section 6) in the panel's **Files** tab. It is not in GitHub, so it is not touched by
updates.

### Things to know about hosting

- **Anyone with admin access to the panel can read your files**, including `.env`. Host with people you trust, and
  reset the token and keys if that ever changes.
- A small allowance (about 256 MB of memory) is plenty.
- **Shared free hosts can be blocked by Discord.** Some free hosts put many bots on one IP address. If Discord
  limits that address, the bot stays online but cannot reply for a while. It lifts by itself. Do not keep
  restarting.
- The bot no longer needs a web port. It does not run a web server.

## 9. Everyday tasks

### Add a slash command
1. Copy `commands/ping.js` and rename it. **The file name must be the command name** (`dice.js` is `/dice`).
2. Change the name, description and what `execute()` does. Keep the `.setContexts(InteractionContextType.Guild)` line.
3. `npm run check`, commit, push, restart. The bot registers the new command on startup, and `/features` lists it.

### Hide a command from `/features`
Add `hidden: true,` as a line inside `module.exports = { ... }` in the command's file, above `data`.

### Make a command owner-only
Add `ownerOnly: true,` the same way. Everyone else gets a private refusal. The owner is `ownerId` in `config.js`.

### Make a command need a Discord permission
Add `.setDefaultMemberPermissions(PermissionFlagsBits.ManageGuild)` to the command's `data`, and check
`interaction.memberPermissions` inside `execute()`. See `commands/botchannel.js` for an example.

### Add a chat trigger
1. Copy `triggers/eyes.js` and rename it (the name is free).
2. Change the `pattern` (the words to react to) and what `execute()` does. Add `examples` so the check can test it.
3. `npm run check`, commit, push, restart.

A trigger file exports `pattern` (a regular expression, with no `g` flag), `execute(message)`, and optionally
`examples` (`shouldMatch` and `shouldNotMatch` lists).

### Add a background service
Add a file in `services/` that exports `start(client)`. It runs once when the bot is ready, and can return a short
note for the console. See `services/reminders.js`.

### Add a greeting, treat reply, tea quote or North Wales picture
Open the file (`commands/hello.js`, `commands/treat.js`, `triggers/tea.js` or `commands/home.js`) and add a line to
the list at the top.

### Write and send an announcement (the changelog)
1. Open `lib/changelog.js`. Replace the `fields` with the new news (and keep only things members can see).
2. Set `date` to today, like `'02/11/2026'`.
3. `npm run check` (it tests Discord's size limits), commit, push, restart.
4. In Discord, use `/previewchangelog` to read it privately.
5. When you are happy, use `/featureupdatechangelog` to send it to every server.

### Add or change something people can edit in a sheet
The sheets are listed in section 5. Add a row, change a cell. For reminders, the bot notices within 5 minutes.

### Change the reminder limits
Edit `reminders` in `config.js` (how far ahead, how often to check, how many tries).

### Add a new Google Sheet for a future feature
1. Share the spreadsheet with the service account email (Editor).
2. Add a line to `sheetIds` in `config.js` with a short name and the ID, and the tab name in `sheetTabs`. The
   start-up check then reports on it.
3. In your code, use `readRange`, `appendRow` and `updateRange` from `lib/sheets.js`. See `commands/cat.js` and
   `commands/addcat.js` for small examples.

## 10. Troubleshooting

| What you see | Likely cause | What to do |
|---|---|---|
| Bot is online but does not reply to words like "tea" | Message Content intent is off | Turn on **Message Content Intent** in the Developer Portal. |
| A slash command is missing in one server | The bot was added without the `applications.commands` scope, or new commands take a few minutes | Open the invite link from section 7 again for that server, then press `Ctrl+R`. |
| `Only Nero's owner can use this command.` | You are not the user in `ownerId` | Check `ownerId` in `config.js`. |
| `You need the Manage Server permission` | `/botchannel` needs that permission | Ask a server admin. |
| `No DISCORD_TOKEN found` | No `.env` file, or the line is missing or still called `TOKEN` | Create `.env` (section 6) with `DISCORD_TOKEN=...`. |
| `An invalid token was provided` | The token was reset or copied wrongly | Reset it in the Developer Portal, copy the new one immediately, update `.env`. The console prints the bot ID inside the token, which should match your Application ID. |
| `Google Sheets is not set up. Missing from the .env file: ...` | Those variables are missing or have the old names | Add them (section 6). |
| `GOOGLE_PRIVATE_KEY looks cut off or damaged` | The key was only partly copied | Copy the whole `private_key` line from the Google JSON file again. |
| Google error about permission, or "not found" | The spreadsheet is not shared with the service account, or the ID is wrong, or the Sheets API is off | Share it (Editor) with the `client_email`, check the ID in `config.js`, enable the Sheets API. |
| `The spreadsheet ... has no tab called ...` | A tab name in `sheetTabs` does not match the spreadsheet | Fix the tab name in `config.js` or rename the tab. |
| `/meme` says the meme maker is not set up | `IMGFLIP_USERNAME` or `IMGFLIP_PASSWORD` is missing from `.env` | Add them and restart. |
| `/meme` puts a person's name on a picture | Some rows were added by the old bot, which saved the name in column A and the words in column B | Swap those two cells by hand in the Meme text sheet. `/meme` only reads column A. |
| A reminder did not go off | The bot was offline (it sends late ones when it returns), or it could not post in the channel and could not DM you | Check the `Sent` column of the Reminders sheet and the console. |
| `That is not a time I understand` | The `when` box has something the bot cannot read | The message shows examples. Try `30m`, `tomorrow 9am` or `2pm in 3 months`. |
| `/featureupdatechangelog` says the changelog has no date | `date` in `lib/changelog.js` is empty | Set it, push, restart (section 9). |
| `No commands were found` at start | The folder is not called `commands` in lowercase | Rename it. Linux hosting treats `Commands` and `commands` as different folders. |
| `Cannot find module` or the server crashes at start | `npm install` did not run, or a file is in the wrong place | Check the console above the error; run `npm install`. |
| Every reply appears twice | Two copies of the bot are running with the same token | Stop one. |
| `git pull` complains about local changes (in the panel console) | A file on the server was edited by hand | Back up the `.env` file, then use the panel's **Reinstall Server**. |
| `npm run check` fails | A file is written wrongly | It names the file and the problem. Fix it and run it again. |

## 11. Rules for writing code here

These are deliberate, and apply to everything in the project:

- **Comment generously.** Every file starts with a comment saying what it is and where it lives. Explain *why*,
  not just *what*, in plain words.
- **Anyone should be able to read it.** Prefer clear names and simple code over clever code.
- **One job per file.** Commands, triggers and services are small, separate files.
- **No em-dashes** (the long dash character) in code, comments, messages or documents. Use a comma, a full stop
  or a hyphen. `npm run check` looks for them.
- **Plain JavaScript, no build step.** Files use `require` (CommonJS).
- **Secrets never go in the code.** They live in `.env`.
- **One broken file must never stop the bot.** Errors are logged with the file name and the user sees a friendly
  message.
- **Run `npm run check` before every push.**

## 12. Glossary

| Word | Meaning |
|---|---|
| **Slash command** | A command you type starting with `/`, which Discord shows in a menu. |
| **Trigger** | The bot reacting to words someone says in a normal message. |
| **Service** | A job that keeps running in the background (like sending reminders). |
| **Embed** | A formatted card in Discord, with a coloured stripe, a title, a picture and a footer. |
| **Ephemeral / private reply** | A reply only the person who used the command can see. |
| **Intent** | A permission switch in the Developer Portal for what events the bot may receive. |
| **Scope** | The kind of access an invite link asks for. Slash commands need `applications.commands`. |
| **Token** | The bot's password for Discord. |
| **Service account** | A Google "robot" with its own email address, which you share spreadsheets with. |
| **Spreadsheet ID** | The long code in a Google Sheet's web address that identifies it. |
| **`.env`** | The file of secrets on each machine. Never uploaded. |
| **Wispbyte** | The hosting service NeroBot runs on. |
| **Repository (repo)** | The project's folder of code on GitHub. |
| **Branch** | A separate line of changes in git. `main` is the one the server runs. |
